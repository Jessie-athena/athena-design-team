# 聲音、語調與格式框架

> SKILL.md 的「Voice & Tone」「i18n 核心規範」需要更細的語調策略或各語系格式時，查閱本檔。

## 品牌聲音 (Voice)
Voice 是固定不變的品牌個性：
- **專業但不冰冷**：以專業為基底，平易近人，不官腔、不命令。
- **清晰直接**：降低理解成本，少廢話。
- **支持性與解決導向**：提供可行解法，減少錯誤焦慮。

## 情境語調矩陣 (Tone Matrix)
Tone 依使用者當下狀態調整。德安是 B2B 專業工具，範例採事務性專業口吻——肯定但不過度熱情、不裝可愛、不用 emoji。

| 情境 | 語調策略 | 規範建議 | 範例 |
| :--- | :--- | :--- | :--- |
| **入門/介紹** | 親切、引導 | 引導完成設定，正向但不浮誇 | 歡迎使用，先從建立第一筆資料開始。 |
| **任務完成** | 簡潔肯定 | 簡短肯定操作，不過度情緒化 | 設定已更新。／已核准。 |
| **指引/幫助** | 清晰、耐心 | 分步式敘述，避免抽象說明 | 請選擇資料來源，再點擊「建立」。 |
| **通知** | 中立、資訊性 | 聚焦資訊傳達，不製造緊張感 | 您的訂閱將於 3 天後續訂。 |
| **錯誤（系統/預期外）** | 同理、安撫 | 提供解法，嚴禁責備 | 系統暫時無法處理，請稍後再試。 |
| **錯誤（驗證/阻擋）** | 明確、事務性 | 直述被擋原因與下一步 | 無法刪除：已被歷史單據引用。 |

## 國際化格式規範 (i18n Formatting)

### 1. 日期格式 (Date)
| 地區 | 格式範例 | 規範 |
| :--- | :--- | :--- |
| **台灣** | 2025/01/01 週一 | 使用 `/` 分割，MM/DD 補零 |
| **日本** | 2025/01/01 月曜日 | 排列順序依地制宜 |
| **越南** | 01/01/2025 Thứ Hai | 視為 B2B 系統核心規範（DD/MM/YYYY） |
| **北美** | Mon, 01/01/2025 | 需支援 Syncfusion 標準格式 |
| **中國** | 2025-01-01 周一 | 使用 `-` 分割 |

### 2. 貨幣格式 (Currency)
- **原則**：金額須**靠右對齊**以便比對位數。
- **範例**：台灣 (NT$ 1,000)、日本 (¥1,000)、越南 (1.000 ₫)。
- 注意小數與千分位符號各地不同（越南以 `.` 為千分位）。

### 3. 姓名欄位結構
- **台灣/日本**：姓 / 名（姓在前）。
- **北美**：First / Last Name。
- **越南**：餐飲系統不強制三段姓名（追求效率）；身份驗證系統則需完整姓名。

### 3.1 性別與稱謂欄位互動邏輯

性別與稱謂為相互依存欄位，變動時依下列規則自動推導：

**稱謂主導（稱謂先選）**

| 稱謂設定 | 結果 |
| :--- | :--- |
| 僅適用男性 | 性別自動設為「男」 |
| 僅適用女性 | 性別自動設為「女」 |
| 通用（男女皆可或皆無） | 不改動性別 |

**性別主導（性別後改）**

| 性別異動為 | 結果 |
| :--- | :--- |
| 男 | 當前稱謂已符合男性 → 保留；否則自動帶入一個男性專屬稱謂（若無則不異動） |
| 女 | 當前稱謂已符合女性 → 保留；否則自動帶入一個女性專屬稱謂（若無則不異動） |
| 多元 / 保密 | 不異動稱謂，兩欄位完全脫鉤 |

> 初始化規則（僅執行一次）：預設稱謂僅適用某性別時，性別預設為對應值；通用稱謂預設性別為「男」。
> 性別為「多元」或「保密」時，不觸發任何推導邏輯。

## 專業術語使用前提
當主要使用者為產業從業人員時，優先使用業界通用術語，但須符合：
1. **業界通用**：非公司內部黑話。
2. **語義唯一**：同一概念僅用一個詞彙。
3. **一致性**：建立報表 vs 新增報表，應統一一個動詞。
4. **性別中立**：用「使用者」「客戶」替代「他／她」，降低文化誤解與歧視風險。

> 各市場標準 UI 詞彙與訊息模板見 `Terminology.md`；ERP 單據專屬術語見 `erp-conventions.md`。

## §4 電話號碼格式 (Phone Number Formats)

### 4.1 顯示格式

E.164 國際標準：`+` + 國碼 + 本地號碼（去掉號碼開頭 0）；`+` 符號必須保留，移除會導致語意歧義。

| 地區 | 格式範例 | 備註 |
| :--- | :--- | :--- |
| **台灣** | `+886 912 345 678` | 去掉號碼開頭 0 |
| **日本** | `+81 90 1234 5678` | 去掉號碼開頭 0 |
| **越南** | `+84 91 234 5678` | 去掉號碼開頭 0 |
| **北美** | `+1 415 555 0172` | 3-3-4 分組 |

> 若產品只接受台灣號碼，可顯示本地格式 `0912345678`。

### 4.2 儲存格式

資料庫統一儲存 E.164（含 `+`、無空格、無分隔符）：`+886912345678`。
確保跨系統資料交換（CRM ↔ ERP ↔ 身份驗證）一致。

### 4.3 輸入驗證

| 項目 | 規則 |
| :--- | :--- |
| **允許字元** | 數字 0–9（禁止空格、破折號、英文字母） |
| **最小長度** | 8 碼 |
| **最大長度** | 12 碼 |

### 4.4 搜尋行為

搜尋層應相容「有 `+`」與「無 `+`」輸入，於搜尋邏輯做正規化處理，不應移除資料庫的 `+` 來配合搜尋。
