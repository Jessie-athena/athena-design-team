# ERP 單據欄位排序規則

> 處理 ERP 設計文件（`docs/notion/**`、`docs/uiflowspec/**`）的「基本資訊」Section 欄序、List Grid 欄序，或 `prototype/project/*.html` 的 Form Header 排版時套用。
> 兩套模型按**模組家族**擇一：進銷存（請購／採購／驗收／退貨／成本調整…）用「三區模型」；財務（出納／應付／應收…）用「雙列模型」。
> 這是欄位**排列順序**的規則，與用字無關；用字見 SKILL.md 本體與 `erp-conventions.md`。角色為何在意此順序見 `personas-mental-models.md`（單據掃描心智）。

---

## 0. 跨家族共通骨幹（先記這個）

1. **單號永遠第 1 格、唯讀** — 草稿階段顯「/」、取號後帶入，非可操作欄。
2. **決策動線**：對象 →（單據類型／稅別）→ 經辦人 → 日期。**有經辦欄時，經辦永遠排在日期前。**
   - 注意：財務單據（憑證、收款）**多半沒有經辦欄**，此條對它們不適用——別硬塞一個經辦欄進去。
3. **唯讀／自動帶入欄集中後段** — 公司別、稅務公司、幣別、科目、日記帳等不擋輸入動線，集中放後段（PSI 隔離區／財務後台列）。

> 兩套模型的主要差別：**結構**（PSI 單段為主／財務固定雙列）與**公司別落點**（PSI 末欄或地點段首／財務後台列靠前）。

---

## 1. 進銷存（PSI）— 三區模型

Header「基本資訊」原則上是**單一序列**，前後兩端固定、只動中段。依識別 → 決策 → 隔離三區排：

### ① 識別區（最前，固定）
本單單號 → 來源單號（採購單號、驗收單號…）→ 條件式關聯財務單據（應付單號／供應商憑證）。

### ② 決策區（中段，照操作先決順序）
- 對象（供應商／客戶／稅別）→ 單據類型（一般／急件／委外…）→ 經辦人 → 日期。
- 雙日期（建立日／交貨日）可並列。
- 「地點／範圍」歸**對象槽位**思考。

### ③ 隔離／後台區（最後，固定）
帳簿／科目／付款方式 → **公司別** → 備註與稽核欄（核准人／取消核准人，條件式）置末。

### 公司別落點（重點，勿一概而論）
- **單一段設計**（驗收單、成本調整單）→ 公司別排**基本資訊末欄**。
- **拆出獨立「地點資訊／公司資訊」段時**（如請購單 v3.0）→ 公司別**領銜該段首位**，後接區域／館別／地點／部門。
- 兩種都符合「公司別屬隔離帶入、不擋決策動線」的精神，差別只在有沒有獨立段。

> 明細（品號／數量／單價）與金額**不在 header**，放 Tab block／Summary Card。

**落地範例：**
- 驗收單（單段、公司別末欄）：`驗收單號 → 採購單號 → 供應商 → 簽收人員 → 驗收日期 → 日記帳 → 付款方式 → 應付科目 → 公司別`
- 成本調整單（單段、公司別末欄）：`成本調整單號 → 地點 → 調整人員 → 調整日期 → 公司別`
- 請購單（拆兩段）：基本資訊 `請購單號 → 請購類型 → 稅別 → 請購人員 → 請購日期 → 交貨日期`；地點資訊 `公司別 → 區域 → 館別 → 地點 → 部門`

## 2. 財務 — 雙列模型

Header「基本資訊」分**兩列**：第一列業務核心、第二列後台／稅務帶入。財務單據通常**沒有經辦欄**。

### 第一列＝業務核心
單號（唯讀，草稿顯「/」）→ 對象（供應商／客戶，必填，有明細後唯讀）→ 主日期（憑證日期／收款日期）→ 次日期（沖轉日期等，選填）→ 產生方式／類型／帳務所屬／日記帳；狀態以 `StatusBadge`（唯讀）呈現。

### 第二列＝後台／稅務帶入（皆唯讀或自動帶入）
科目（如貸方會計科目）→ **公司別** → 部門（選定後帶入稅務公司）→ 稅務公司 → 幣別 → 摘要。

### 公司別落點
公司別固定在**後台列靠前位置**，但不必死板第 1 格：
- 供應商憑證：後台列**列首**（公司別 → 部門 → 稅務公司 → 幣別）。
- 收款作業：後台列在**貸方科目之後**（貸方科目 → 公司別 → 部門 → 摘要）。

### List 欄序（收款作業範例）
`勾選 → 單號 → 狀態 Badge → 帳務所屬 → 日期 → 類型 → 金額`；金額欄一律右對齊 `text-right tabular-nums`。

**落地範例：**
- 供應商憑證：第一列 `憑證單號 → 供應商 → 憑證日期 → 沖轉日期 → 產生方式`；第二列 `公司別 → 部門 → 稅務公司 → 幣別`
- 收款作業：第一列 `收款單號 → 收款日期 → 帳務所屬 → 收款類型 → 日記帳`；第二列 `貸方會計科目 → 公司別 → 部門 → 貸方傳票摘要`

## 3. 兩套模型對照

| 面向 | 進銷存（三區模型） | 財務（雙列模型） |
|---|---|---|
| 結構 | 單段為主（識別→決策→隔離）；少數拆「基本資訊＋地點資訊」 | 固定雙列（業務列／後台列） |
| 單號 | 第 1 格、唯讀 | 第一列第 1 格、唯讀 |
| 經辦人 | 有，排日期前 | 多半無此欄 |
| 決策動線 | 對象→(類型)→經辦→日期 | 對象→主日期→次日期 |
| **公司別** | 單段→末欄；拆段→地點資訊段首位 | 後台列靠前（列首或科目之後） |
| 稅務／幣別 | 隔離區 | 後台列 |
| 明細／金額 | Tab block／Summary Card（不在 header） | 同（不在 header） |

---

## 4. 反例（已被 PM 糾正過，務必避免）

- ❌ 把**單號搬到 header 末尾** — 單號永遠第 1 格（PSI 曾誤排被糾正）。
- ❌ PSI 單段設計卻把**公司別塞在決策區中段** — 應在末欄（或拆段時領銜地點資訊段）。
- ❌ 寫財務文件時照搬 PSI，把**公司別壓到 header 最末尾** — 財務公司別在後台列靠前。
- ❌ **硬給財務單據加一個「經辦人」欄** — 財務多無此欄。
- ❌ 把**經辦人排到日期後** — 有經辦欄時永遠在日期前。
- ❌ 把明細欄（品號／數量／單價）或金額拆解塞進 header。

## 5. 審查／撰寫檢查清單

撰寫或審查 §基本資訊 Section 時逐項確認：

- [ ] 已判定模組家族（進銷存 → 三區；財務 → 雙列）。
- [ ] 單號在第 1 格且標唯讀（草稿顯「/」）。
- [ ] 有經辦欄時，動線為 對象→(類型)→經辦→日期，經辦在日期前；財務無經辦欄則略過。
- [ ] 公司別位置正確：PSI 單段末欄／PSI 拆段時地點資訊段首位／財務後台列靠前。
- [ ] 唯讀帶入欄（公司別／稅務公司／幣別／科目／日記帳）集中後段，未擋決策動線。
- [ ] 明細與金額不在 header（放 Tab block／Summary Card）。
- [ ] 缺的欄（無次日期、無單據類型、無稅務公司、無經辦）直接跳過，不硬補，順序維持既有相對位置。
