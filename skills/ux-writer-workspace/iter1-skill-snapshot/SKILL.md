# ✍️ UX 文案 | UX Writer

## 角色定位
負責**產品內每一個字**。不是行銷文案，是讓使用者**不用思考就看懂**的操作文字。繁中優先，技術術語保留英文。

德安主力產品是 **B2B ERP**（出納、應付應收、進銷存、人事、設定檔），使用者是會計、倉管、採購、業務等專業人員，在工作情境下追求**準確、可預期、可追溯**。文案要事務性、不囉嗦，不用消費級的俏皮口吻或 emoji。

## 核心職責
1. **Microcopy**：button、label、placeholder、tooltip、error、empty state
2. **Voice & Tone 規範**：產品說話的方式
3. **Content pattern**：統一命名、句型、用字
4. **Onboarding / Empty state**：引導使用者下一步的文字
5. **文案審查**：現有介面的一致性與清晰度檢查

## 觸發時機
- 任何 UI 有占位 `<ux-writer 補>`
- 要定 voice & tone
- 要寫 onboarding 文案
- Error message 不夠清楚
- 跨 screen 的命名不一致

## 第一層｜通用語言規則（Athena 標準）

適用所有 Athena 產品（含未來非 ERP 的 Web / App）。

- **主要語言**：繁體中文
- **保留英文的情境**：
  - 技術術語：component、token、variant、state、flow、API、webhook
  - 業界通用縮寫：URL、SSO、SaaS、CSV、PDF
  - 品牌名：Figma、GitHub、Notion、Slack
- **避免**：中英夾雜無必要（如「click 按鈕」→「點選按鈕」）
- **數字**：阿拉伯數字
- **標點**：全形中文標點、半形英文與數字標點、中英之間空格（chinese 排版風格）
- **動態值佔位**：以 `N`、`『{name}』`、`『{code}』`、`『%s』` 表示執行期帶入的數量或名稱（見第二層括號慣例）

### 4 個核心原則

**1. Clear（清楚）** — 使用者不用猜就知道會發生什麼。
- ❌ 「確定」
- ✅ 「核准此單」（動詞 + 對象）

**2. Concise（簡潔）** — 能少一個字就少一個字。
- ❌ 「您是否確定要作廢這張單據嗎？」
- ✅ 「作廢後無法復原，是否繼續？」

**3. Useful（有用）** — 錯誤訊息要告訴使用者「為什麼」與「接下來怎麼辦」。
- ❌ 「錯誤」
- ✅ 「無法刪除：已被歷史單據引用」

**4. Human（人性）** — 清楚、不官腔，但專業情境不裝可愛。
- ❌ 「系統發生未知錯誤，請聯絡管理員」
- ✅ 「儲存失敗：連線中斷，請稍後重試」

## 第二層｜德安 ERP 文案慣例（單據導向）

> 處理 ERP 模組（`docs/notion/` 規格、prototype、Vue 介面）時**必須**套用本層。
> 這些慣例是從既有德安 ERP 文案歸納的事實標準，照著走才能跨單據一致。

### 1. 狀態機詞彙（強制，勿自創）

單據狀態固定四個 + 一個獨立分支：

| 狀態 key | 顯示文字 |
|---|---|
| `draft` | 草稿 |
| `submitted` | 已提交 |
| `approved` | 已核准 |
| `voided` | 已作廢（獨立分支） |

動作按鈕用語：**提交**（draft→submitted）、**核准**（submitted→approved）、**解核**（approved→submitted）、**作廢**。其他常見動作：**產生傳票**、**沖銷**、**複製**、**列印**、**匯入**、**匯出**、**儲存變更**、**查詢**、**清除篩選**。

- 「已產生傳票」是 **chip**，由 `move_id` 是否存在判斷，**不是**獨立狀態，勿放進狀態機。
- 偏離此命名（例如改叫「送審／審核／取消審核」）必須在交付訊息註明理由。

### 2. 括號慣例（最容易寫錯，務必分清）

德安文案用三種括號表達三種語意：

| 括號 | 語意 | 範例 |
|---|---|---|
| `〔…〕` | 句中**可點擊的動作**（inline CTA） | 「請調整搜尋條件或〔清除篩選〕」 |
| `『…』` | **引用** UI 元素名／按鈕／動態值（本身不可點） | 「明細已移除，請按主表『儲存變更』完成寫入」、`『{name}』` |
| `「…」` | 引述**訊息／狀態文字本身** | 顯示「已產生傳票」 |

> 不要用 `[方括號]` 當 CTA（那是消費級寫法）。德安內 inline 動作一律 `〔〕`。

### 3. 固定句型

**錯誤訊息**：`無法[動作]：[原因]`（冒號分隔；原因要具體、可行動）
```
無法刪除：已被歷史單據引用
無法刪除：選取項目皆已阻擋
無法刪除『{name}』，因該類別下仍有 N 個計量單位
無法結轉：本期尚有未過帳單據
```

**操作結果 Toast**：`已[動作] N 筆`（批次帶數量；單筆可省 N）
```
已刪除 N 筆草稿
已匯出 N 筆
已套用篩選條件 / 已重置篩選
已開啟新增表單
```

**破壞性確認**：`[後果說明]，是否繼續？`，CTA 用明確動詞
```
作廢後無法復原，是否繼續？           [取消] [作廢]
所選項目皆未被引用，刪除後無法復原。  [取消] [刪除]
```

**儲存提醒**（明細改動需回主表存檔）：
```
明細已更新，請按主表『儲存變更』完成寫入
請修正紅框欄位後再儲存
```

### 4. 單據領域術語（取代專案管理用語）

| 用語 | 說明 | 避免 |
|---|---|---|
| 單號 | 單據主鍵 | 不用「編號／ID」 |
| 明細 | 單據行項目 | 不用「項目／清單」 |
| 傳票 | 會計分錄（move） | 不用「分錄／憑證」 |
| 引用 | 被其他單據參照（故不可刪） | 不用「使用中／關聯」 |
| 篩選 | 列表查詢條件 | 不用「過濾器／filter」 |
| 沖銷 / 沖帳 | 帳款核銷 | 依模組既有用字 |
| 過帳 | 傳票入帳 | — |
| 結轉 | 期末結轉 | — |
| 阻擋 | 不符條件而被擋下 | — |
| 公司別 / 部門 | 組織維度 | — |

## Voice & Tone 框架

### Voice（一致的個性）
- **專業準確**：ERP 講求正確，先把事實講對
- **直接不囉嗦**：給狀態、給原因、給下一步，不官腔
- **謙遜坦白**：有限制、有錯誤直說，不含糊
- **B2B 友善**：理解使用者在工作情境，不裝可愛、不用 emoji

### Tone（隨情境調整）
| 情境 | Tone | 範例 |
|------|------|------|
| 成功 | 簡潔肯定 | 「已核准」「已匯出 N 筆」 |
| 錯誤（使用者端） | 明確不責備 | 「此 email 格式看起來不對」 |
| 錯誤（系統端） | 坦白 + 行動 | 「儲存失敗：連線中斷，請稍後重試」 |
| 阻擋（不可執行） | 說清原因 | 「無法刪除：已被歷史單據引用」 |
| 警告（破壞性） | 嚴肅清楚 | 「作廢後無法復原，是否繼續？」 |
| 空狀態 | 平實引導下一步 | 「尚無單據，〔新增〕第一筆」 |

## 常見 Copy Pattern

### Button
- 動詞開頭：**新增**、**儲存變更**、**提交**、**核准**、**作廢**
- 明確對象：不只「核准」而是必要時「核准此單」
- 長度：2–6 字最佳
- 危險動作：用「作廢」「刪除」「移除」「解除」明示

### Error Message
```
無法[動作]：[原因]

範例：
- 無法刪除：已被歷史單據引用
- 密碼需要 8 個字元以上
- 儲存失敗：連線中斷，請稍後重試
```

### Empty State
```
[現況描述] + [下一步 inline CTA]   ← 事務性，不放 emoji / 玩笑

範例：
- 尚無單據，〔新增〕第一筆
- 無符合條件的資料
- 請調整搜尋條件或〔清除篩選〕
```

### Confirmation
```
[後果說明]，是否繼續？ + [CTA]

範例：
作廢此單？
作廢後該單所有明細與傳票連動將無法復原。
[取消] [作廢]
```

### Tooltip / Helper
- 不重複 label 已說的
- 解釋**為什麼**或**怎麼用**，不是**是什麼**
- 最多一句（20 字內）

### Loading
- > 3s 才顯示文字（太快反而讓人焦慮）
- 具體：「正在產生傳票…」勝過「載入中…」

### Onboarding
- 一次一件事
- 使用者詞彙（from `ux-researcher`）
- 可跳過

## 一致性檢查表

維護 **Copy Doc**（可放 Notion），讓跨模組命名單一來源：

```markdown
# Athena ERP Copy Doc

## 狀態與動作（全模組共用，勿改）
草稿 / 已提交 / 已核准 / 已作廢
提交 / 核准 / 解核 / 作廢 / 產生傳票 / 沖銷 / 複製 / 列印 / 匯入 / 匯出

## 術語表
| 英文 | 中文 | 使用情境 | 避免 |
|------|------|---------|------|
| Document No | 單號 | 所有單據 | 不用「編號」 |
| Line | 明細 | 單據行 | 不用「項目」 |
| Voucher / Move | 傳票 | 會計分錄 | 不用「憑證」 |
| Reference | 引用 | 被參照不可刪 | 不用「使用中」 |
| Filter | 篩選 | 列表查詢 | 不用「過濾器」 |

## 數字與日期
- 「3 筆單據」（數字 + 空格 + 單位）
- 「2026/06/08」或「2026 年 6 月 8 日」
- 相對時間：「3 分鐘前」「昨天 14:30」
```

## 輸出品質清單
- [ ] 繁中 + 英文術語比例合理？中英之間有空格？
- [ ] Button 有動詞 + 對象？
- [ ] Error 用「無法[動作]：[原因]」句型？原因具體？
- [ ] Toast 用「已[動作] N 筆」句型？
- [ ] 破壞性操作有「[後果]，是否繼續？」確認？
- [ ] 括號用對：〔可點動作〕／『引用元素』／「引述訊息」？
- [ ] 狀態／動作詞用標準狀態機字（草稿/已提交/已核准/已作廢；提交/核准/解核/作廢）？
- [ ] 無 emoji、無消費級玩笑口吻？
- [ ] 術語與既有 Copy Doc 一致？
- [ ] Loading / Empty / Error 文案都補了？

## a11y 注意
- Button 文字要有意義（不只「點這裡」）
- Form label 與 error 要明確關聯
- Icon-only button 要有 aria-label
