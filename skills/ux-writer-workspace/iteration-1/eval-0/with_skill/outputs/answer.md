# 採購退貨單 — 作廢相關文案

> 套用德安 ERP 第二層文案慣例：破壞性確認句型 `[後果說明]，是否繼續？`、錯誤句型 `無法[動作]：[原因]`、括號慣例（`『』` 引用 UI 元素／`「」` 引述訊息）、狀態機標準動詞（作廢）。

---

## (1) 作廢確認對話框

按下『作廢』時跳出。

| 區塊 | 文案 |
|---|---|
| **標題** | 作廢此單？ |
| **說明** | 作廢後該單明細與庫存連動將無法復原，是否繼續？ |
| **次要按鈕** | 取消 |
| **主要按鈕（危險）** | 作廢 |

```
作廢此單？

作廢後該單明細與庫存連動將無法復原，是否繼續？

                                   [取消]  [作廢]
```

**設計說明**

- 標題用問句明示這是需要決定的破壞性操作；說明句套用 `[後果說明]，是否繼續？` 句型，先講不可復原的後果再請使用者確認。
- 後果聚焦採購退貨單實際牽動的「明細與庫存連動」，比泛稱「資料」更具體可預期。
- CTA 用明確動詞「作廢」（非「確定」），與觸發按鈕同字，使用者點下去前就知道會發生什麼；「作廢」為危險動作樣式（danger）。

---

## (2) 已產生傳票、不允許作廢的錯誤訊息

該單已產生傳票，作廢被阻擋時跳出。

```
無法作廢：本單已產生傳票

請先沖銷對應傳票後，再執行作廢。
```

**設計說明**

- 主訊息套用 `無法[動作]：[原因]` 句型，冒號前是被擋的動作（作廢），冒號後是具體原因（已產生傳票）。
- 「傳票」為單據領域標準術語（會計分錄 move），不寫「分錄／憑證」。
- 補一句可行動的下一步（先沖銷傳票），符合「錯誤訊息要告訴使用者為什麼與接下來怎麼辦」。「沖銷」為帳款核銷標準動詞。
- 「已產生傳票」本身是由 `move_id` 判斷的狀態事實，此處以原因敘述出現，不視為獨立狀態。

> 若該情境有對應的沖銷入口可直接跳轉，下一步可改為 inline CTA 寫法：
> `請先〔沖銷傳票〕後，再執行作廢。`（`〔〕` 表句中可點擊動作）
