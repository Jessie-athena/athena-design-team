# ERP 介面文案審查

依德安 ERP 文案慣例（狀態機詞彙、〔〕/『』/「」括號慣例、`無法[動作]：[原因]` 句型、無 emoji、Loading 具體化）逐條審查。

---

## 1.『確定要刪除嗎？』

**判定：需修改**

問題：
- 違反 Clear 原則——「確定」不是動詞 + 對象，沒講後果。
- 破壞性操作應套用固定句型 `[後果說明]，是否繼續？`，並用明確動詞當 CTA。
- 刪除是不可復原動作，必須先告知後果讓使用者可預期。

**修正：**

```
刪除後無法復原，是否繼續？        [取消] [刪除]
```

> 若是批次刪除草稿，可帶數量：「將刪除 N 筆草稿，刪除後無法復原，是否繼續？」CTA 仍為〔取消〕〔刪除〕。

---

## 2.『載入中...』

**判定：需修改**

問題：
- 不夠具體。skill 的 Loading 規範要求「具體：正在產生傳票… 勝過 載入中…」。
- 標點用了半形刪節號 `...`，繁中應用全形 `…`。
- 另注意：> 3 秒才需顯示文字，太快的 loading 不必上字。

**修正（依實際情境擇一具體說法）：**

```
正在產生傳票…
正在查詢…
正在匯出…
```

> 若情境真的無法具名，至少改標點為全形：「載入中…」。但優先用具體動作詞。

---

## 3.『刪除成功！🎉』

**判定：需修改**

問題：
- 含 emoji 🎉，且帶驚嘆號的消費級俏皮口吻——B2B ERP 專業情境禁用 emoji、不裝可愛。
- 未套用操作結果 Toast 句型 `已[動作] N 筆`。
- 「成功」屬冗字，事務性 Toast 用「已刪除」即可（簡潔肯定的 Tone）。

**修正：**

```
已刪除 N 筆            （批次）
已刪除                （單筆可省 N）
```

---

## 4.『點這裡清除篩選』

**判定：需修改**

問題：
- 「點這裡」違反 a11y 與 Clear 原則——按鈕／連結文字要有意義，不可用「點這裡」。
- inline 可點擊動作（CTA）應使用 `〔…〕` 括號，而非平鋪文字或 `[方括號]`。
- 「清除篩選」用語正確（屬標準動作詞、「篩選」為正規術語），保留。
- 常見於空狀態，應採 `[現況描述] + [下一步 inline CTA]` 模式。

**修正：**

```
請調整搜尋條件或〔清除篩選〕
```

> 若只是單純的 inline 動作而非空狀態，最小修正為：〔清除篩選〕。

---

## 5.『送審』

**判定：需修改**

問題：
- 偏離標準狀態機動作詞。draft → submitted 的動作固定用語為「**提交**」，不可自創「送審／審核」。
- skill 明訂：偏離命名（如改叫「送審」）必須在交付訊息註明理由——預設一律回正規詞。

**修正：**

```
提交
```

> 對應狀態：草稿（draft）→〔提交〕→ 已提交（submitted）。後續動作為〔核准〕〔解核〕〔作廢〕。
