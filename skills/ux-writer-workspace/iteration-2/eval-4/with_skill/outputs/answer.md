# 重印發票 — 確認彈窗文案（餐飲 iPad POS）

## 情境判斷
- 產品線：餐飲（FBM / iPad POS）→ 套用現場效率慣例：句式短、問句結構、正向動作在右。
- 訊息性質：**決策性**彈窗（重印發票是會實際吐單／影響出單的資料動作，非單純告知），故按鈕用**動作導向動詞**，不用中性的「確認 / OK」。
- 強阻斷必要性：重印會多印一張實體發票，現場容易誤觸，需明確再確認一次 → 採通知型彈窗而非 Toast。

## 文案

**標題**
```
是否重印發票？
```

**內文（說明影響，給可預期結果）**
```
將重新列印目前帳單的發票，請確認出單機已備妥紙張。
```

> 內文採事務性、給下一步（確認紙張），不責備、不放 emoji。

## 兩個按鈕（含方向）

| 位置 | 按鈕文字 | 角色 |
| :--- | :--- | :--- |
| **左**（返向操作） | 取消 | 中止，回到結帳畫面 |
| **右**（正向操作 · 主按鈕） | 重印發票 | 執行重印，動詞 + 對象 |

- 依餐飲慣例：正向操作（動詞）在右、返向操作（取消）在左。
- 主按鈕沿用具體動詞「重印發票」（與標題動詞一致），避免「確定 / OK」這類模糊中性詞，店員一眼可辨要做什麼。

## 操作後回饋（Toast，低阻斷）
```
已重印發票
```
> 完成後以 Toast 即時回饋、自動消失，不再彈窗阻斷現場節奏。
