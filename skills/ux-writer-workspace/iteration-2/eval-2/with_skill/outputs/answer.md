# ERP 介面文案審查

依 ux-writer SKILL.md（通用原則 §1、句型 §2、各垂直 §5）與 `references/erp-conventions.md`（ERP 單據慣例）逐條審查。

---

## 1.『確定要刪除嗎？』 ❌ 需修改

**問題**
- 屬破壞性確認，但句型不符 ERP 慣例。erp-conventions §3 規定破壞性確認用 `[後果說明]，是否繼續？`，先講後果再問。
- 「確定…嗎？」是模糊的中性問句，沒交代刪除後果（可否復原、影響範圍），使用者無法做有依據的決定（違反 §1 行動導向 / Clear）。
- 搭配的按鈕若用「確定／取消」屬中性詞，決策性彈窗應用動作導向按鈕（SKILL §2 Toast vs 彈窗）。

**修正版**
```
刪除後無法復原，是否繼續？          [取消] [刪除]
```
（若該筆可能被引用，再細分：所選項目皆未被引用，刪除後無法復原。`[取消] [刪除]`）

---

## 2.『載入中...』 ❌ 需修改

**問題**
- 違反 §2 Loading 原則：具體優於籠統，「載入中…」太籠統，應說明正在做什麼。
- 標點錯誤：用了半形三點 `...`，中文文案省略號應用全形刪節號 `…`（§1 標點規範）。
- 提醒：>3s 才需顯示文字，太快顯示反而造成焦慮（此為觸發時機，非文字本身問題）。

**修正版**（依實際情境擇一具體化）
```
正在載入資料…
正在產生報表…
正在查詢…
```

---

## 3.『刪除成功！🎉』 ❌ 需修改

**問題**
- 含 emoji 🎉，B2B 工具一律禁用 emoji、禁消費級慶祝口吻（§1、Voice & Tone §4）。
- 驚嘆號 + 「成功」過度熱情，不符事務性語氣。
- 句型不符 ERP Toast 慣例：操作結果應為 `已[動作] N 筆`（erp-conventions §3）。
- 此為即時操作回饋，應為 Toast（低阻斷、自動消失）。

**修正版**
```
已刪除 N 筆          （批次，帶數量）
已刪除              （單筆，可省 N）
```

---

## 4.『點這裡清除篩選』 ❌ 需修改

**問題**
- 「點這裡」無意義，違反 a11y §8（button 文字要有意義，不可只說「點這裡」）。
- 句中可點擊動作（inline CTA）應用 `〔〕`，不是裸文字也不是 `[方括號]`（erp-conventions §2 括號慣例）。
- 「篩選」用語正確（§4 術語表，勿用「過濾器／filter」），保留。

**修正版**
```
inline CTA 寫法：請調整搜尋條件或〔清除篩選〕
獨立按鈕：     清除篩選
```
（對應 Toast 回饋：已重置篩選 / 已清除篩選）

---

## 5.『送審』 ❌ 需修改

**問題**
- 偏離 ERP 強制狀態機命名。狀態機動作固定為 **提交**（draft→submitted），不用「送審／審核」（erp-conventions §1）。
- 偏離此命名須在交付訊息註明理由；此處無特殊理由，應改回標準詞。

**修正版**
```
提交
```
（draft→submitted 用「提交」；submitted→approved 用「核准」；approved→submitted 用「解核」）
