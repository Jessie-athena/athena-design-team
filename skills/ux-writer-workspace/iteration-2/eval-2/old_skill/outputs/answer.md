# ERP 介面文案審查

依德安 ERP 文案慣例（狀態機詞彙、〔〕/『』/「」括號、無 emoji、破壞性確認句型、Loading 具體化）逐條審查。

---

## 1.『確定要刪除嗎？』

**問題（需修改）**

- 違反破壞性確認句型 `[後果說明]，是否繼續？`：只問「確定」，未說明後果（刪除無法復原），使用者得自己猜。
- 「確定」過於模糊，不符 Clear 原則；CTA 應改用明確動詞「刪除」而非「確定」。

**修正版**

> 刪除後無法復原，是否繼續？　〔取消〕〔刪除〕

（若為批次刪草稿，可帶數量：「將刪除 N 筆草稿，刪除後無法復原，是否繼續？」）

---

## 2.『載入中...』

**問題（需修改）**

- 不具體。Loading 文案應說明「正在做什麼」，具體動作勝過泛用「載入中」。
- 標點錯誤：用了半形 `...`，中文情境應使用刪節號 `…`。
- 提醒：> 3s 才需顯示文字，太快顯示反而讓人焦慮（此為觸發時機，非文字本身問題）。

**修正版**

> 正在查詢…（依實際情境替換，如「正在產生傳票…」「正在匯出…」）

---

## 3.『刪除成功！🎉』

**問題（需修改）**

- 含 emoji 🎉，違反「B2B 專業情境不裝可愛、不用 emoji」硬規則。
- 驚嘆號為消費級俏皮口吻，事務性 Toast 不需要。
- 未用 Toast 標準句型 `已[動作] N 筆`。

**修正版**

> 已刪除 N 筆（單筆可省 N：「已刪除」）

---

## 4.『點這裡清除篩選』

**問題（需修改）**

- 「點這裡」是無意義連結文字，違反 a11y 規則（Button/連結文字要有意義，不只「點這裡」）。
- inline 可點擊動作應使用 `〔〕` 括號標示 CTA，而非「點這裡」這種口語指引。
- 通常出現在空狀態，應採 `[現況描述] + [下一步 inline CTA]` 格式。
- 「清除篩選」為標準動作用語，保留正確。

**修正版**

> 無符合條件的資料，請調整搜尋條件或〔清除篩選〕

（若僅需動作本身：〔清除篩選〕）

---

## 5.『送審』

**問題（需修改）**

- 違反狀態機詞彙（強制，勿自創）。draft→submitted 的動作固定用語為「提交」，不可自創「送審／審核」。
- 偏離標準命名須在交付訊息註明理由，此處無理由，應正名。

**修正版**

> 提交

---

## 小結

5 條全部需修改：

| 原文案 | 主要問題 | 修正版 |
|---|---|---|
| 確定要刪除嗎？ | 缺後果說明、CTA 模糊 | 刪除後無法復原，是否繼續？〔取消〕〔刪除〕 |
| 載入中... | 不具體、半形 `...` | 正在查詢…（依情境替換） |
| 刪除成功！🎉 | emoji + 驚嘆號、未用標準句型 | 已刪除 N 筆 |
| 點這裡清除篩選 | 「點這裡」無意義、未用〔〕 | 無符合條件的資料，請調整搜尋條件或〔清除篩選〕 |
| 送審 | 自創狀態機用語 | 提交 |
