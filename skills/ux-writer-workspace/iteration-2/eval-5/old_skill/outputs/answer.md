# 兩種彈窗的按鈕文案

## 1. 權限不足彈窗（純告知，讀完就關）

**按鈕文字：`知道了`**

只放這一顆按鈕。

- 內容範例：「您沒有此功能的權限，請聯絡管理員開通。」
- 這是 **acknowledgement（告知型）** 彈窗，使用者讀完關閉即可，不會觸發任何後續動作。
- 既然沒有任何「會發生什麼事」的決策，就**不該**提供「確認 / 取消」這種二選一，那會讓人誤以為按了會執行某件事。一顆「知道了」最誠實：它只代表「我看到了」。
- 不用「確定」——依本 skill「Clear」原則，「確定」要求動詞＋對象，但這裡根本沒有對象可確定；改用表達「已讀」語意的「知道了」。
- 也可用「關閉」，但「知道了」更貼近使用者當下的心理動作（已理解、可離開），語氣也更人性。

## 2. 刪除確認彈窗（破壞性操作）

**按鈕文字：`取消` ／ `刪除`**（兩顆）

- 套用本 skill 第二層「破壞性確認」句型：`[後果說明]，是否繼續？`，CTA 用明確動詞。
- 內容範例：
  ```
  刪除這筆資料？
  刪除後無法復原。
  〔取消〕  〔刪除〕
  ```
- 主要動作 CTA 直接用危險動詞「刪除」（不用「確定」），讓使用者按下前就清楚會發生什麼；「取消」提供安全退出。
- 主／次按鈕的擺位與樣式（危險色）由 UI 規範處理，但文字本身一定要是動詞。

## 兩者差在哪

| | 權限不足彈窗 | 刪除確認彈窗 |
|---|---|---|
| 性質 | 告知（acknowledgement） | 決策（destructive confirmation） |
| 使用者要不要做選擇 | 不用，讀完關掉 | 要，二選一且有後果 |
| 按鈕數量 | 1 顆 | 2 顆 |
| 按鈕文字 | `知道了` | `取消` / `刪除` |
| 為何這樣寫 | 沒有後續動作，給單一「已讀」出口；給二選一反而誤導 | 操作不可復原，必須讓使用者明確選擇執行或退出，CTA 用危險動詞明示後果 |

核心差異：**告知型彈窗沒有「會發生什麼」，所以只給一個關閉的出口；破壞性彈窗有「按下去會發生不可復原的事」，所以要用動詞 CTA＋安全退出，讓使用者在按下前就懂後果。** 按鈕數量與用字反映的是「使用者是否需要做一個有後果的決定」。
