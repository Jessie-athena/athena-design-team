# 兩個彈窗的按鈕文字

## 1. 權限不足彈窗（純告知）

> 您沒有此功能的權限，請聯絡管理員開通。

**按鈕：知道了**

只有一顆按鈕。

## 2.「刪除這筆資料」彈窗（決策）

> 刪除後無法復原，是否繼續？

**按鈕：〔取消〕〔刪除〕**

兩顆按鈕：返向（取消）在左、正向動作（刪除）在右。

---

## 兩者差在哪

關鍵差別在於**這則彈窗是「讓你知道」還是「要你做決定」**——這決定了按鈕用「告知性」用語還是「動作導向」用語。

| | 權限不足彈窗 | 刪除確認彈窗 |
|---|---|---|
| 彈窗性質 | **告知性**：權限限制說明，不涉決策 | **決策性**：會異動資料（刪除） |
| 使用者要做的事 | 讀完關掉，不會有任何後續操作 | 必須在「真的刪」與「不刪」之間做選擇 |
| 按鈕數 | 1 顆 | 2 顆（取消 + 動作） |
| 按鈕用語 | **「知道了」** | **動作導向動詞「刪除」** + 「取消」 |
| 為什麼 | 沒有「決定」可下，用中性的確認詞反而誤導使用者以為按下去會「開通權限」 | 必須讓使用者清楚這顆按鈕會觸發不可逆的破壞性動作 |

### 重點說明

**告知性彈窗的按鈕統一用「知道了」**，並**禁用「確認／確定／關閉／OK」**等中性詞。原因：
- 權限不足這則訊息使用者讀完就關，按鈕語意應該是「我已知曉」，而不是「我確認執行某動作」。
- 用「確定」會讓人誤以為按下去能改變什麼（例如以為會送出開通申請），但其實什麼都不會發生——這違反「可預期」。

**決策性彈窗（刪除／作廢／送出等資料異動）必須用動作導向動詞**，把按鈕標成它真正會做的事：
- 用「刪除」而非「確定」，使用者一眼就知道按下去的後果。
- 刪除是破壞性動作，文案先說明後果（「刪除後無法復原，是否繼續？」），再讓使用者按明確的〔刪除〕。

### 補充：先確認是否真需要強阻斷彈窗

依寫作慣例，下手寫按鈕前先問「這則訊息是否真的需要強阻斷彈窗」：
- **權限不足**確實需要強阻斷彈窗——必須確保使用者知曉自己無權限、知道該找誰，所以保留通知型彈窗 +「知道了」。
- 若只是操作完成的回饋（如「已刪除 3 筆」），則不該用彈窗，改用會自動消失的 **Toast**，且通常無按鈕。
