# CRS 預約失敗訊息 — 多語系破版檢查與改寫

> 產品線：飯店 CRS（中央訂房系統）。依 SKILL §5 飯店慣例，CRS 現場詞彙尚在建立中，**詞彙待補、勿自創**——下方越南文部分按此原則處理（見 §4）。

---

## 1. 多語系破版風險診斷

原句：
> 預約失敗！因為 {hotel_name} 的 {room_type} 有庫存衝突，請調整時間或日期。

| 風險 | 說明 | 對應規範 |
| :--- | :--- | :--- |
| **句中含 2 個變數** | `{hotel_name}`、`{room_type}` 都嵌在句子中段。各語言語序不同（英/越的所有格、修飾語位置與中文相反），翻譯時極易拆錯、卡死語序。 | SKILL §3「避免句中變數」「一句一變數」 |
| **驚嘆號＋消費級口吻** | 「預約失敗！」帶情緒。B2B 工具應事務性、不過度情緒化、不用 emoji/驚嘆號。 | SKILL §1、§4 Voice & Tone |
| **「因為…」報錯口吻** | 以「失敗＋因為」開頭偏報錯，未直接給「狀態＋下一步」。此為可預期的業務阻擋（庫存衝突），應走驗證/阻擋句型 `無法[動作]：[原因]`。 | SKILL §2 錯誤訊息（驗證/阻擋類） |
| **「時間或日期」模糊** | 庫存衝突的可調整對象其實是「入住／退房日期」。CRS 慣例詞建議與 PM 確認後統一（如 C/I、C/O）。 | SKILL §5 飯店慣例 |
| **英/越偏長** | 英文、越南文通常比中文長，此訊息含房型＋飯店名兩個變數，Toast/Dialog 須預留長文字空間，勿假設與中文等寬。 | SKILL §3「翻譯破版風險」 |

**結論**：需重構為「主訊息（無變數，事務性）＋ 變數獨立成 `Label: Value` 明細列」，把兩個變數從句子裡抽出來，避免語序破版，並改驗證/阻擋句型。

---

## 2. 改寫結構（翻譯友善）

把一句話拆成三層：**標題（阻擋原因，無變數）→ 衝突明細（Label: Value，每列一變數）→ 下一步指引**。

```
標題：無法完成預約：所選房型庫存不足
明細：
  飯店：{hotel_name}
  房型：{room_type}
指引：請調整入住日期，或改選其他房型。
```

- 標題、指引皆**無變數** → 翻譯不會卡語序。
- 變數各自獨立成列、**一列一變數** → 符合「一句一變數」。
- 「庫存衝突」改為使用者看得懂的「庫存不足」；下一步從「時間或日期」收斂為「入住日期 / 改選房型」這兩個 CRS 操作者真正能做的動作（日期詞彙待 PM 確認 C/I 用語後統一）。

## 3. 繁中 ＋ 英文版本

### 繁體中文
```
標題：無法完成預約：所選房型庫存不足
飯店：{hotel_name}
房型：{room_type}
請調整入住日期，或改選其他房型。
```

### English
```
Title: Booking failed: selected room type is unavailable
Hotel: {hotel_name}
Room type: {room_type}
Please adjust the check-in date or choose another room type.
```

> 兩版皆把變數抽成 `Label: Value`、主句無內嵌變數，可獨立翻譯不破版。英文長度略長於中文，元件（Dialog 內文）需預留換行空間。

## 4. 越南文（依 CRS 慣例待確認）

依 SKILL §5：飯店 CRS 現場詞彙尚在建立中，**勿自創**。下方為依 `Terminology.md` 通用詞（Error / Hotel 等）推得的**暫擬版**，「房型／入住日期」等 CRS 專屬詞須先與 PM 確認既有用語再定稿：

```
Tiêu đề: Đặt phòng thất bại: loại phòng đã chọn không còn trống
Khách sạn: {hotel_name}
Loại phòng: {room_type}
Vui lòng đổi ngày nhận phòng hoặc chọn loại phòng khác.
```
> ⚠️ 待 PM 確認：「Loại phòng（房型）」「ngày nhận phòng（入住日期）」是否符合 CRS 既有越語用詞，確認後回填 `Terminology.md`。

## 5. 加碼：『入住日期』必填未填錯誤訊息

類型：驗證/阻擋（必填未填）。採 `Terminology.md` §4 必填檢查模板 `請輸入 {FieldName}` / `Please enter {FieldName}`，變數置尾、不破版。

### 繁體中文
```
請輸入『入住日期』
```

### English
```
Please enter "Check-in date"
```

> 變數（欄位名）置於句尾，符合 i18n 模板；繁中沿用 ERP `『』` 標示欄位的慣例，英文以引號標示。CRS 若另有入住日期既有用語，以 PM 確認版為準。

## 6. 套用規範摘要
- 破版主因＝**句中 2 變數**：已抽成 `Label: Value`、一列一變數（SKILL §3）。
- 錯誤分類：庫存衝突＝**驗證/阻擋類**，改 `無法[動作]：[原因]`＋下一步（SKILL §2）。
- 去除驚嘆號與消費級口吻，維持 B2B 事務性語調（SKILL §1、§4）。
- 越南文與 CRS 專屬詞**標為待確認、未自創**（SKILL §5 飯店慣例）。
- 必填訊息套用 `Terminology.md` 必填模板。
