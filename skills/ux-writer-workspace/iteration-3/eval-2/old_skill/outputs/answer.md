# ERP 介面文案審查

對象：德安 ERP（單據導向）。依 `SKILL.md` 通用原則／句型，及 `references/erp-conventions.md` 的狀態機詞彙、括號慣例、固定句型逐條審查。五條全部需修改。

---

## 1.『確定要刪除嗎？』

**判定：需改。**

問題：
- **屬破壞性確認，句型錯誤。** ERP 破壞性確認句型為 `[後果說明]，是否繼續？`，須先講後果（刪除後無法復原），不能只丟一句問句。
- **「確定」是該避免的中性詞。** 決策性彈窗按鈕要用動作導向（「刪除」），而非「確定/OK」。原句把決策包成「確定嗎」，未明示動作與後果。
- 缺下一步／後果，使用者無法預期影響。

建議：

```
所選項目刪除後無法復原，是否繼續？   [取消] [刪除]
```

> 若該筆可能被引用，先做阻擋判斷，被擋時改用阻擋句型：`無法刪除：已被歷史單據引用`。

## 2.『載入中...』

**判定：需改。**

問題：
- **籠統。** SKILL.md Loading 規範：「具體優於籠統」，要講正在做什麼。
- **半形刪節號 `...` 不合標點規範。** 中文應使用全形刪節號 `…`。
- 觸發時機提醒：載入 < 3 秒不應顯示文字（太快反而焦慮），> 3 秒才顯示。

建議（依實際情境擇一具體化）：

```
正在載入單據…
正在產生報表…
正在查詢…
```

---

## 3.『刪除成功！🎉』

**判定：需改。**

問題：
- **emoji 嚴禁。** B2B 工具不用 emoji、不裝可愛。
- **驚嘆號過度情緒化。** 任務完成語調應「簡潔肯定」，不過度熱情。
- **未用 ERP Toast 句型。** 操作結果應為 `已[動作] N 筆`（批次帶數量，單筆可省 N），以 Toast 低阻斷呈現、自動消失。

建議：

```
已刪除          （單筆）
已刪除 3 筆     （批次，帶實際數量）
```

---

## 4.『點這裡清除篩選』

**判定：需改。**

問題：
- **a11y 違規。** 按鈕／連結文字要有意義，禁止「點這裡」這類無意義指代。
- **未用 ERP inline CTA 括號慣例。** 句中可點擊動作應以 `〔…〕` 包覆，不用方括號、不用「點這裡」。
- 「清除篩選」本身已是標準動作詞（見狀態機動作清單），直接當 CTA 即可。

建議：

```
請調整搜尋條件或〔清除篩選〕
```

> 若為獨立按鈕，按鈕文字直接為「清除篩選」。

---

## 5.『送審』

**判定：需改。**

問題：
- **偏離強制狀態機命名。** ERP 狀態機動作固定為 **提交**（draft→submitted）／核准／解核／作廢；「送審」「審核」屬自創用語。
- 「語義唯一」原則：同一動作跨單據只用一個詞，混用「送審」會破壞跨模組一致性。

建議：

```
提交
```

> 規範允許例外：若該模組業務確實是「送出給上層審核」且 PM 已確認沿用「送審」，須在交付訊息註明偏離理由；否則一律用「提交」。
