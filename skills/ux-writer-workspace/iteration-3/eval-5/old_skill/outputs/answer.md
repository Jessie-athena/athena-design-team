# 彈窗按鈕文案：權限通知 vs. 刪除確認

## 結論（先看這個）

| 彈窗類型 | 按鈕文字 |
|---|---|
| 權限通知（讀完關掉，不做任何操作） | **知道了**（單一按鈕） |
| 刪除這筆資料（會異動資料） | **〔取消〕〔刪除〕**（左取消、右動詞） |

---

## 1. 權限通知彈窗 → 用「知道了」

**「您沒有此功能的權限，請聯絡管理員開通」** 屬於 **告知性通知型彈窗**：只是讓使用者「知道一件事」，不涉及任何決策，使用者讀完就關掉。

按鈕用 **「知道了」**，且只需要這一顆按鈕。

- 依規範，告知性彈窗（系統公告、權限限制、不可異動說明）按鈕統一用「知道了」。
- **禁用**「確認 / 確定 / 關閉 / OK」這類中性詞——它們暗示使用者剛「做了一個選擇」，但這裡其實沒有任何選擇可做，會造成語意誤導。

> 補充：先確認這則訊息是否真的需要強阻斷的彈窗。如果情境允許，純告知也可以考慮用低阻斷、自動消失的 Toast；但「權限不足」通常希望確保使用者明確看到，用彈窗 +「知道了」是合理的。

---

## 2. 刪除確認彈窗 → 用動作導向動詞「刪除」

**「刪除這筆資料」** 屬於 **決策性彈窗**：使用者要在「真的刪」與「不刪」之間做決定，而且刪除是會異動資料的破壞性操作。

按鈕用**動作導向**的動詞，不用中性詞：

```
所選項目刪除後無法復原，是否繼續？      〔取消〕〔刪除〕
```

- 正向（破壞性）動作按鈕直接寫 **「刪除」**，讓使用者一眼看出按下去會發生什麼——避免用「確定」這種看不出後果的字。
- 破壞性操作的內文要先講後果（如「刪除後無法復原」），句型 `[後果說明]，是否繼續？`。
- 版面慣例：返向操作（取消）在左、正向操作（刪除）在右。

---

## 3. 兩者差在哪？

核心差別是 **這則訊息要使用者「知道」還是要使用者「做決定」**：

| 面向 | 權限通知 | 刪除確認 |
|---|---|---|
| 彈窗性質 | 告知性（單純通知） | 決策性（資料異動） |
| 使用者要做什麼 | 讀完、關掉，無操作 | 在「刪 / 不刪」之間抉擇 |
| 按鈕數量 | 一顆（知道了） | 兩顆（取消 + 動作） |
| 按鈕用字 | **「知道了」**（不可用確認/確定/關閉/OK） | **動作動詞「刪除」**（不可用確定/OK） |
| 為什麼 | 沒有選擇可做，中性詞會誤導成「做了選擇」 | 動詞讓使用者看清按下去的後果，尤其破壞性操作 |

一句話判斷法：**訊息只是「讓你知道」→ 用「知道了」；訊息要你「做決定」→ 用動作詞。** 兩類都不要用「確定 / OK」這種看不出意圖與後果的中性按鈕。
