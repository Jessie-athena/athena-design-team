# 兩個彈窗的按鈕文案

## 結論先講

| 彈窗 | 性質 | 按鈕文案 |
|---|---|---|
| 「您沒有此功能的權限，請聯絡管理員開通」 | 告知性（純通知，不涉決策） | **知道了**（單一按鈕） |
| 「刪除這筆資料」 | 決策性（資料異動，使用者要做決定） | **取消** ｜ **刪除**（兩個按鈕） |

---

## 1. 權限不足彈窗 →「知道了」

這個彈窗只是「讓使用者知道一件事」，他讀完關掉就好、不會做任何操作。這屬於**告知性的通知型彈窗**（系統公告、權限限制、不可異動說明這一類）。

- 按鈕統一用 **「知道了」**。
- **禁用**「確認 / 確定 / 關閉 / OK」這類中性詞——因為這裡沒有任何東西要「確認」，使用者只是承認自己看到了訊息。「知道了」準確描述了他唯一能做的事。
- 只需要**一顆按鈕**，不需要「取消」（沒有可取消的動作）。

文案本身也順手調整，符合通用寫作原則（清晰、給下一步、不責備）：

```
標題：權限不足
內文：您沒有「{功能名稱}」的使用權限，請聯絡系統管理員開通。
按鈕：知道了
```

> 順帶一提：在做決定前先問——這則訊息是否真的需要強阻斷的彈窗？權限提示如果不影響當下操作流程，有時用 Toast 或行內提示就夠了，不必每次都跳彈窗擋住使用者。但本題情境是「必須確保使用者知曉」，用通知型彈窗是合理的。

## 2. 刪除確認彈窗 →「刪除」（搭配「取消」）

「刪除這筆資料」要使用者**做一個決定**（要不要真的刪），而且是不可復原的破壞性操作，這屬於**決策性的通知型彈窗**。

- 主按鈕用**動作導向**的具體動詞 **「刪除」**，不要用「確定 / OK」。讓使用者在按下去前，從按鈕上就確認自己要做的是「刪除」這件事。
- 搭配一顆返向的 **「取消」**。
- 破壞性操作要先說後果再問——句型 `[後果說明]，是否繼續？`：

```
標題：刪除確認
內文：刪除後無法復原，是否繼續？
按鈕：[取消] [刪除]
```

> ERP 單據情境的補充（可逆心智）：要刪的若是**草稿**（還沒成立），用「刪除」；若是**已提交 / 已核准**的單據（已成立、有軌跡），應改用 **「作廢」**而非刪除，並說明「作廢會留紀錄、不可復原」。動詞要對齊資料的真實可逆性。

---

## 3. 兩者差在哪？

核心判斷只有一句：**這則訊息是要使用者「知道」，還是要他「做決定」？**

| 比較點 | 權限不足（告知性） | 刪除確認（決策性） |
|---|---|---|
| 使用者要做什麼 | 只是讀完、知曉，無操作 | 要在「做 / 不做」之間做選擇 |
| 按鈕語意 | 承認「我看到了」 | 觸發一個具體動作 |
| 用詞 | 中性的「知道了」 | 動作導向的具體動詞「刪除 / 作廢」 |
| 按鈕數量 | 1 顆（知道了） | 2 顆（取消 + 動作） |
| 為什麼不能互換 | 告知性用「刪除 / 確認」會讓人以為要做事；決策性用「知道了 / OK」則隱藏了真正後果，使用者不知道自己按下去會發生什麼 | |

一句話：**只是讓你知道 → 用「知道了」；要你做決定 → 用動作詞（並把後果寫在前面）。**
