# 採購退貨單 — 表單頁文案

> 模組：進銷存／採購退貨單（已成立單據，狀態機 draft / submitted / approved / voided）
> 讀者：採購、倉管。採購在意退貨鏈是否對得上、倉管在意庫存連動，已產生傳票時會計在意帳務追溯。
> 慣例依據：`erp-conventions.md` §3 破壞性確認句型、§2 括號慣例、§1 狀態機動作用語。

---

## (1) 作廢確認對話框

採購退貨單是已成立的單據（非草稿），只能「作廢」留痕、不能物理刪除；作廢會連動還原本單已退出的庫存，因此後果說明同時點出「庫存還原」與「不可復原」兩件事。

| 區塊 | 文案 |
|---|---|
| 標題 | 確認作廢採購退貨單？ |
| 說明 | 作廢將還原本單已退出的庫存，且作廢後無法復原，是否繼續？ |
| 按鈕（左）| 取消 |
| 按鈕（右）| 作廢 |

版面示意：

```
確認作廢採購退貨單？

作廢將還原本單已退出的庫存，且作廢後無法復原，是否繼續？

                                          [取消] [作廢]
```

> 若該單尚未產生傳票、亦無庫存異動，可精簡為「作廢後無法復原，是否繼續？」；含庫存連動時務必保留庫存還原說明（倉管最在意的料帳一致）。

---

## (2) 已產生傳票、不允許作廢的錯誤訊息

屬「驗證／阻擋類」可預期業務阻擋，用事務性句型 `無法[動作]：[原因]`，原因講使用者懂的因果並給下一步（先沖銷傳票），不丟系統內部原因。

```
無法作廢：本單已產生傳票，請先沖銷傳票後再作廢
```

> 「沖銷」為德安帳款核銷既有用語（會計慣用詞）；若本模組傳票回沖的既有用字為其他詞（如「回沖／反過帳」），改採該模組既有用字，勿自創。
> 此訊息只需告知無法作廢的原因與下一步，建議以阻擋型 Toast 或 inline 錯誤呈現即可；若採用通知型彈窗則屬告知性，按鈕用「知道了」。
