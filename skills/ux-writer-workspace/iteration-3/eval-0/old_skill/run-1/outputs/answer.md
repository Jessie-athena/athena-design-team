# 採購退貨單 — 表單頁文案

> 產品線：ERP（進銷存）。套用 ERP 單據慣例：狀態機（草稿／已提交／已核准／已作廢）、`無法[動作]：[原因]` 阻擋句型、破壞性確認 `[後果說明]，是否繼續？`、`〔〕`／`『』`／`「」` 三種括號。

---

## (1) 作廢確認對話框（決策性彈窗）

破壞性操作須強阻斷，CTA 用明確動詞，正向操作（作廢）在右、返向操作（取消）在左。

| 區塊 | 文案 |
|---|---|
| 標題 | 確認作廢採購退貨單？ |
| 說明 | 作廢後本單將無法復原，明細與退貨數量一併失效。是否繼續？ |
| 按鈕（左：取消／右：作廢） | `[取消]` `[作廢]` |

完整呈現：

```
確認作廢採購退貨單？

作廢後本單將無法復原，明細與退貨數量一併失效。是否繼續？

                                          [取消]  [作廢]
```

---

## (2) 已產生傳票、不可作廢的錯誤訊息（驗證／阻擋類）

可預期的業務阻擋，用事務性句型 `無法[動作]：[原因]`，並補可行動的下一步。「傳票」為 ERP 單據領域術語（不用「分錄／憑證」）。

主訊息：

```
無法作廢：本單已產生傳票
```

含下一步（建議版）：

```
無法作廢：本單已產生傳票，請先沖銷傳票後再作廢。
```

> 說明：
> - 「已產生傳票」是由 `move_id` 是否存在判斷的狀態，作廢前須先處理傳票，故以阻擋類錯誤呈現，非系統錯誤（不套同理安撫句型、不丟技術碼）。
> - 若該模組沖銷傳票的入口為句中可點擊動作，可改寫為：`無法作廢：本單已產生傳票，請先〔沖銷傳票〕後再作廢。`（`〔〕` 表 inline CTA）。
> - 此訊息為純告知性阻擋，若以彈窗呈現且不涉決策，按鈕用「知道了」；若僅需輕量回饋，建議改用 Toast。
```
