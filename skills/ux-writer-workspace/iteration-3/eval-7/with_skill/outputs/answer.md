# 請購單核准後不可改金額 — 阻擋訊息與 helper

## 情境判讀

- **模組／單據**：採購模組 · 請購單
- **讀者**：採購人員。心智模型是「請購 → 採購 → 收貨」一條鏈，慣用詞為請購單、供應商、交期；對「已核准」的單抱**可逆心智**——已成立、有軌跡，不能再隨意改。
- **訊息類型**：可預期的業務阻擋（已核准後鎖金額），屬**驗證／阻擋類**，用事務性句型 `無法[動作]：[原因]`，不責備、不丟技術碼。
- **慣例**：金額是 UI 欄位名，引用用 `『…』`；狀態用固定詞「已核准」。

---

## 阻擋訊息

```
無法修改『金額』：請購單已核准
```

**若要再補可行動的下一步（採購人員看得懂的解法）：**

```
無法修改『金額』：請購單已核准。如需調整，請先解核
```

> 「解核」是狀態機既有動作（已核准 → 已提交），採購人員能據此知道下一步去哪做，而不只是被擋住。若該模組權限不開放採購人員自行解核，改寫為「如需調整，請洽核准主管」。

---

## Helper 說明（一句，金額欄位旁）

```
核准後金額即鎖定，避免採購與請購對不上
```

- 解釋**為什麼**鎖（不是重複「這是金額」），點到採購人員最在意的「鏈上對得起來、不怕對不上」。
- 17 字，控制在一句、20 字內。

---

## 取捨說明

- **句型**：屬可預期業務阻擋，故用事務性 `無法[動作]：[原因]`，不用同理安撫句型（那留給連線中斷／伺服器異常）。
- **原因寫法**：講使用者懂的因果（「請購單已核准」），不寫「狀態不符 / 欄位唯讀 / record locked」這類內部說法。
- **括號**：`『金額』` 為引用 UI 欄位名；全程無 `[方括號]` 當句中 CTA。
- **元件建議**：此為欄位層級即時阻擋，建議用行內錯誤或 Toast，不必動用強阻斷彈窗；若以彈窗告知純不可異動說明，按鈕用「知道了」。
- **i18n**：訊息無句中變數，已採 `『欄位名』` 引用結構；採購單據術語目前以繁中為準，需多語版本時依 erp-conventions 與 PM 確認產業慣用詞。
