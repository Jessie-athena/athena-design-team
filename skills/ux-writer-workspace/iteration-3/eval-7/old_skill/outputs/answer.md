# 請購單核准後不可改金額 — 阻擋訊息與 helper

## 情境
採購模組請購單，狀態進入「已核准」後金額已鎖定，使用者試圖修改金額時需擋下。

屬於**驗證／阻擋類**錯誤（可預期的業務阻擋），用 ERP 事務性句型 `無法[動作]：[原因]`，不責備、不丟技術碼。

---

## 阻擋訊息（建議採用）

```
無法修改金額：請購單已核准
```

說明：採購人員一看就懂「為什麼不能改」——因為單子已經核准了，不需理解狀態機術語。冒號前是擋下的動作、冒號後是具體原因。

### 若需補可行的下一步（單據已過核准、欲改金額的常見做法）

```
無法修改金額：請購單已核准。如需調整，請先〔解核〕後再修改
```

- `〔解核〕` 用句中可點擊動作括號（inline CTA），對應狀態機既有動作「解核」（已核准 → 已提交）。
- 若該模組權限不開放採購人員自行解核，則省略此句，只保留第一行，避免引導使用者去點無權限的動作。

---

## Helper 說明（一句）

放在金額欄位旁，解釋「為什麼鎖住」，不重複 label：

```
核准後金額即鎖定，不可修改
```

（13 字，未超過 20 字上限；說明原因而非欄位是什麼。）

---

## 採用理由與注意事項

- **講法貼近採購人員**：用「請購單已核准」「金額已鎖定」這類單據作業的直覺說法，不寫「狀態為 approved」「違反狀態機約束」等系統內部用語。
- **句型合規**：阻擋類用 `無法[動作]：[原因]`，與其他 ERP 單據一致。
- **括號慣例**：句中可點動作用 `〔解核〕`；`解核` 為狀態機既有動作詞，未自創。
- **下一步是否提供，依權限決定**：採購人員若無解核權限，提供〔解核〕反而造成挫折，建議由 PM 確認該角色權限後再決定是否保留第二版。
