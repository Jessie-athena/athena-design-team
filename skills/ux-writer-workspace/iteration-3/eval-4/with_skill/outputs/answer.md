# 餐飲 iPad POS — 重印發票確認彈窗

## 情境與讀者
- **產品線**：餐飲 FBM / iPad POS，結帳畫面。
- **讀者**：現場店員——站著、單手操作、邊招呼客人邊結帳，要「快、看一眼就懂、不要擋住下一步」。
- **慣用詞彙**：結帳、發票、重印（沿用，不改成「補印」「再次列印」）。
- **在意點**：發票對不對、彈窗會不會卡住出餐節奏。重印牽涉實體發票輸出，需確認一次避免誤印，因此用強阻斷彈窗（決策性）而非 Toast。

## 文案

**標題／主文（問句結構，POS 句式更短）**

```
是否重印發票？
```

> 若需補一行說明（畫面空間允許時）：
> `將重新列印這筆消費的發票。`

**按鈕**

| 位置 | 按鈕文字 | 角色 |
|------|---------|------|
| 左 | 取消 | 返向操作 |
| 右 | 重印 | 正向操作（動詞） |

## 設計依據
- **POS 問句結構**：`是否 + 動詞 + 受詞？` →「是否重印發票？」（SKILL §7 餐飲慣例）。
- **按鈕方向**：正向操作（動詞）在右、返向操作（取消）在左（SKILL §7、personas §店員）。
- **決策性彈窗用動作導向按鈕**：右鈕用具體動詞「重印」，不用「確認／確定／OK」等中性詞（SKILL §4 Toast vs 通知型彈窗）。
- **具體動詞優先**：「重印」勝過「列印」「再印一次」（SKILL §7）。
- **同理、不責備、無 emoji**：純詢問語氣，B2B 工具一律不裝可愛（SKILL §3、§6）。

## 重印成功後的回饋（補充）
即時回饋改用 Toast，不再擋手：

```
已重印發票
```
