# 請購單 Header 欄位排序

## 結論先講

請購單屬於**進銷存（PSI）／採購**家族，套用「**三區模型**」。而且請購單是「**拆段設計**」——Header 分成兩段：**基本資訊**段與**地點資訊**段。

- **公司別放在「地點資訊」段的第 1 位（領銜該段）**，不是基本資訊段、也不是塞在決策動線中段。
- 之所以領銜地點資訊段，是因為一旦把公司別這類「組織維度／自動帶入」欄位拆成獨立段，它就成為該段的分類起點（公司別 → 區域 → 館別 → 地點 → 部門，由大到小逐層收斂）。

## 完整欄序

### 段一｜基本資訊

```
請購單號 → 請購類型 → 稅別 → 請購人員 → 請購日期 → 交貨日期
```

| 順位 | 欄位 | 說明 |
|---|---|---|
| 1 | 請購單號 | **第 1 格、唯讀**；草稿階段顯「/」，取號後帶入。永遠不可移到末尾。 |
| 2 | 請購類型 | 單據類型（決策區），對象槽位之後、經辦之前。 |
| 3 | 稅別 | 與類型同屬決策前置條件。 |
| 4 | 請購人員 | 經辦人。**經辦永遠排在日期前。** |
| 5 | 請購日期 | 主日期。 |
| 6 | 交貨日期 | 次日期；雙日期並列。 |

### 段二｜地點資訊

```
公司別 → 區域 → 館別 → 地點 → 部門
```

| 順位 | 欄位 | 說明 |
|---|---|---|
| 1 | **公司別** | **領銜此段（首位）**。屬隔離／自動帶入欄，不擋決策動線。 |
| 2 | 區域 | 公司別之下的組織層級。 |
| 3 | 館別 | 逐層收斂。 |
| 4 | 地點 | |
| 5 | 部門 | |

## 為什麼這樣排（心智模型）

請購人員（採購）掃描單據的順序是：**識別 → 決策 → 隔離**。

1. **識別區（最前、固定）**：先確認「這是哪張單」→ 請購單號打頭、唯讀。
2. **決策區（中段、照操作先決順序）**：對象／類型 → 稅別 → 經辦 → 日期。使用者要先決定「請購什麼性質、誰請、何時要」，這條動線不能被自動帶入的欄位打斷。
3. **隔離／後台區（最後、固定）**：公司別、區域、館別、地點、部門這些**自動帶入、不需逐字輸入**的組織維度集中後段——請購單把它們獨立成「地點資訊」段，因此公司別作為分類起點領銜該段。

## 常見排錯（務必避免）

- ❌ 把公司別塞進「基本資訊」段的決策區中段——會打斷對象→類型→經辦→日期的輸入動線。
- ❌ 把公司別壓到整個 Header 的最末尾——那是財務雙列模型的反例，PSI 拆段時公司別要領銜地點資訊段。
- ❌ 把請購單號搬到 Header 末尾——單號永遠第 1 格（PSI 曾因此被 PM 糾正）。
- ❌ 把請購人員排到日期後——有經辦欄時，經辦永遠在日期前。
- ❌ 把明細（品號／數量／單價）或金額拆進 Header——明細放 Tab block、金額放 Summary Card，都不在 Header。

## 對照：若是「單段」PSI 單據

請購單是少數拆段的 PSI 單據。多數 PSI 單據（如驗收單、成本調整單）是**單段**設計，此時公司別改放**基本資訊末欄**：

- 驗收單：`驗收單號 → 採購單號 → 供應商 → 簽收人員 → 驗收日期 → 日記帳 → 付款方式 → 應付科目 → 公司別`
- 成本調整單：`成本調整單號 → 地點 → 調整人員 → 調整日期 → 公司別`

兩種落點（拆段領銜地點段 vs 單段末欄）都符合同一原則：**公司別屬隔離帶入欄，不擋決策動線**。
