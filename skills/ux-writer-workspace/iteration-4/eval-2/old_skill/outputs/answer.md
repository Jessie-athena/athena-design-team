# 供應商憑證（財務／應付）「基本資訊」Header 欄位順序

## 結論：完整欄序

```
1. 單號
2. 供應商        ← 對象
3. 憑證類型      ← 類型
4. 經辦          ← 經辦
5. 憑證日期      ← 日期
6. 公司別 / 部門  ← 隔離帶（末段）
```

> 依模組實際欄位，「決策區」內可再細化（如類型後接幣別、日期內含到期日／帳款期別），但**心智順序不變**：先確認是哪張單 → 再判斷對象與性質 → 最後才是組織歸屬維度。

---

## 排序依據（單據掃描心智模型）

德安 ERP 使用者整天在處理單據，視線與決策順序固定為：

**單號（這是哪張）→ 決策區（對象 → 類型 → 經辦 → 日期）→ 隔離帶入（公司別等）**

欄位 label 與 Header 區的資訊先後要對齊此順序，使用者才不用回頭找。逐段說明如下。

### 1. 單號（首位）
- 單據主鍵，使用者拿到單第一個確認「這是哪一張」。
- 用「單號」，不用「編號／ID」（單據領域術語）。
- 通常為系統產生、唯讀。

### 2. 供應商（對象）
- 應付情境的**對象**就是供應商——這是會計／採購判斷整張單的第一個依據（「這是付給誰的」）。
- 對應 cm.partner 性質的對象欄，採購人員以「廠商」為敘事主軸，故緊接單號之後。

### 3. 憑證類型（類型）
- 對象確認後，使用者接著判斷這張憑證的**性質**（例如進貨憑證／費用憑證／預付沖轉等，依模組定義）。
- 決定後續欄位與傳票走向，故排在對象之後、經辦之前。

### 4. 經辦（經辦）
- 負責這張單的人，屬決策區，協助判斷責任歸屬與後續追蹤。

### 5. 憑證日期（日期）
- 決策區末段。日期影響期別／帳務歸期，會計在意「期別有沒有結錯」，故放在類型、經辦判斷完之後。
- 若有到期日、帳款期別等衍生日期，緊接本欄。

### 6. 公司別／部門（隔離帶，末段）
- 公司別、部門是**組織維度**（隔離帶），不是使用者判斷單據內容的主軸，固定放 Header 最後。
- 常見錯誤是把公司別、建立時間放最前面——這違反掃描心智，使用者得跳過組織欄才找到真正要判斷的對象與類型。

## 該角色最在意的點（供 label / helper 撰寫參考）

供應商憑證的主要讀者是**會計／財務**，其次是**採購**：

- **會計**腦中是「借貸必須平衡、每筆都要能追溯到傳票」的帳務邏輯——看一張憑證先想「這會變成哪張傳票、金額對不對得起來、期別對不對」。故金額等式與傳票關係要透明；「已產生傳票」以 **chip** 呈現（由 move_id 是否存在判斷，不是獨立狀態，不放進狀態機）。
- **採購**以「請購 → 採購 → 收貨 → 退貨」一條鏈在想事情，重視關聯單據（這張憑證來自哪張採購單／收貨單），可在 Smart Bar 呈現。

## 附帶用字慣例（避免踩雷）

- 狀態機固定四值：草稿 / 已提交 / 已核准 / 已作廢（獨立分支），勿自創「送審／審核」。
- 術語：用「單號」「傳票」「明細」「引用」「公司別／部門」，勿用「編號／分錄／憑證（指 move 時）／關聯」。
- 必填欄位 label 後標紅色 `*`；唯讀欄用 readonly 呈現，不用 disabled（語意不同）。
