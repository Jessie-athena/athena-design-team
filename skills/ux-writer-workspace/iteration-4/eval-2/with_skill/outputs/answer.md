# 供應商憑證（財務／應付）「基本資訊」Header 欄位順序

## 先判家族：財務 → 雙列模型

供應商憑證屬**財務（應付）**模組家族，套用「**雙列模型**」（而非進銷存的三區模型）。
雙列模型的精神：第一列放**業務核心**欄位（使用者下單時主動填／判斷），第二列放**後台／稅務帶入**欄位（多為唯讀或自動帶入）。

財務單據的兩個關鍵特性，先記住：

- **沒有「經辦人」欄** — 不要硬塞一個經辦欄進去（這是常見反例）。
- **公司別在後台列靠前** — 不像進銷存那樣壓到 header 最末尾。

---

## 完整欄序

### 第一列＝業務核心

```
憑證單號 → 供應商 → 憑證日期 → 沖轉日期 → 產生方式
```

| 欄位 | 性質 | 說明 |
|---|---|---|
| 憑證單號 | 唯讀 | 永遠第 1 格；草稿階段顯「/」，取號後帶入，非可操作欄 |
| 供應商 | 必填 | 對象（業務核心）；有明細後轉唯讀 |
| 憑證日期 | 必填 | 主日期 |
| 沖轉日期 | 選填 | 次日期；無此需求可略過，順序維持不變 |
| 產生方式 | 帶入／類型 | 單據類型／產生方式 |

> 狀態以 `StatusBadge`（唯讀）呈現，不佔欄位序列。

### 第二列＝後台／稅務帶入（皆唯讀或自動帶入）

```
公司別 → 部門 → 稅務公司 → 幣別
```

| 欄位 | 說明 |
|---|---|
| 公司別 | 後台列**列首**（財務公司別落點靠前） |
| 部門 | 選定後帶入稅務公司 |
| 稅務公司 | 由部門帶入 |
| 幣別 | 自動帶入 |

> 如有摘要欄，置於後台列末（如收款作業的「貸方傳票摘要」落點）。

---

## 為什麼這樣排（心智依據）

1. **單號永遠第 1 格、唯讀** — 跨家族共通骨幹，使用者第一眼要確認「這是哪張單」。
2. **第一列照會計判斷動線** — 對象（供應商）→ 主日期（憑證日期）→ 次日期（沖轉日期）→ 產生方式，對齊使用者掃描順序，不用回頭找。
3. **唯讀帶入欄集中第二列、不擋輸入動線** — 公司別／部門／稅務公司／幣別都是自動帶入或唯讀，集中後台列才不會打斷第一列的填寫節奏。
4. **公司別在後台列列首，不在最末** — 這是財務與進銷存最大差異。進銷存單段設計把公司別放末欄；財務則固定在後台列靠前位置。

---

## 對照：與進銷存（三區模型）的差別

| 面向 | 供應商憑證（財務／雙列） | 進銷存（三區） |
|---|---|---|
| 結構 | 固定雙列（業務列／後台列） | 單段為主（識別→決策→隔離） |
| 經辦人 | **無此欄** | 有，且排日期前 |
| 公司別落點 | 後台列**列首**（靠前） | 單段→末欄／拆段→地點段首位 |
| 明細／金額 | 不在 header（放 Tab／Summary Card） | 同 |

---

## 須避免的反例

- ❌ 照搬進銷存，把**公司別壓到 header 最末尾** — 財務公司別在後台列靠前。
- ❌ 硬給供應商憑證**加一個「經辦人」欄** — 財務單據多無此欄。
- ❌ 把**憑證單號搬到 header 末尾** — 單號永遠第 1 格、唯讀。
- ❌ 把明細欄（品號／數量／單價）或金額拆解塞進 header — 放 Tab block／Summary Card。
